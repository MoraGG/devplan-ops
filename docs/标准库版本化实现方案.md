# 标准库版本化 · 实现方案

> 范围：房地产开发运营计划系统（代建三级计划管理）· P0 系统管理增强
> 依据：`docs/需求规格说明书_v0.2.md` §6.1（系统管理·可扩展）、`db/design.md` §8（标准库版本化）、交接提示词 §四.1
> 目标：给标准节点规则库加**版本维度**，支持「按版本回看」与「一键回滚（自动留痕）」，且已发布项目计划（plan_node）不受影响。

---

## 0. TL;DR

| 项 | 结论 |
|---|---|
| 核心模型 | **两态**：后台日常改规则 =「工作副本」（即时生效）；点「发布版本」才固化为可回溯的**版本快照**（整库全量） |
| 版本化范围 | 仅**标准库** `std_node_rule` + `std_node_dependency`；项目级 `project_node_rule` / `project_node_fixed` 不参与 |
| 必须改的引擎点 | `db/engine.py` `_load()` 两处 `SELECT` 加 `WHERE is_active=1`（否则回滚产生的旧行会被误读） |
| 既有可用基础 | `std_node_dependency` 已预留 `version_no/is_active/effective_from` 三列（代码未用）；`rule_change_log` 已存在 |
| 已建项目 | 不受影响——`plan_node` 是套模板时的快照，引擎只认「当前生效集」 |

## 1. 现状盘点（改造前）

| 对象 | 现有状态 | 版本化缺口 |
|---|---|---|
| `std_node_rule` | 仅存当前生效分支（DELETE+INSERT 覆盖式） | **无** `version_no/is_active/effective_from` 三列 |
| `std_node_dependency` | 仅存当前生效边（UPDATE/INSERT 覆盖式） | 三列 DDL 已预留但**代码从未读写**，值可能为 NULL |
| `rule_change_log` | 已记录每次动作（before/after JSON） | 是「动作流水」，非「可回放的版本快照」 |
| 引擎 `_load` | 读全表无过滤 | 回滚后历史行会污染计算 |
| `std_node` | 有 `version_no` 列（默认1），但节点本身基本不变 | 仅作占位 |

**结论**：版本化的实质工作量 = ① 给 `std_node_rule` 补齐三列；② **激活** `std_node_dependency` 已预留的三列；③ 引擎加 `is_active` 过滤；④ 新增版本目录表与发布/回滚逻辑；⑤ UI 入口。

---

## 2. 设计模型：两态（工作副本 + 版本快照）

采用**两态**而非「每次保存即一版」，理由：运营部通常是「攒一批改动 → 统一发布」，且避免单节点小改产生版本爆炸。

```
┌─────────────┐   点「发布版本」    ┌──────────────────┐
│ 工作副本     │ ───────────────▶  │ 版本快照 vN       │
│ (is_active=1 │                   │ (当前 is_active=1 │
│  当前生效集) │   点「回滚到 vK」  │  全量规则 + 目录) │
└─────────────┘ ◀───────────────  └──────────────────┘
                                 （复制 vK 为最新版，旧版 is_active=0）
```

- **工作副本**：所有 `is_active=1` 的规则行。后台单节点编辑即更新它（原地 UPDATE / 旧行 `is_active=0`+插新行），**即时生效于后续新建项目**。
- **版本快照**：每次「发布版本」把工作副本**全量复制**为 `version_no = max+1` 的新行集（旧版 `is_active=0`），并写一条 `std_rule_version` 目录记录（版本号、名称、生效日、操作员、备注、变更摘要）。
- **回滚**：选某历史版本 → 复制其全部行为「最新版」（`is_active=1`，旧版 `is_active=0`）→ 写 `rule_change_log`（action=`版本回滚`）→ 自然生效。

> 存储成本：每次发布复制 `std_node_rule`（~80 行）+ `std_node_dependency`（~143 行）。148 节点规模下，百级版本仅数千行，可忽略。MVP 用全量快照最稳、最好回看；差异存储留待后续优化。

## 3. 数据模型改动

### 3.1 `std_node_rule` 补列（ALTER，双库通用）

```sql
ALTER TABLE std_node_rule
  ADD COLUMN version_no   INT      DEFAULT 1,
  ADD COLUMN is_active     TINYINT  DEFAULT 1,
  ADD COLUMN effective_from DATE    NULL;
```

### 3.2 新增 `std_rule_version`（版本目录）

```sql
CREATE TABLE std_rule_version (
  id            INT PRIMARY KEY AUTO_INCREMENT,
  version_no    INT NOT NULL UNIQUE,
  name          VARCHAR(120),                       -- 版本名，如「2026Q3 管线调整」
  note          VARCHAR(255),                       -- 备注/变更说明
  effective_from DATE,                              -- 该版本从哪天起对新项目生效
  operator      VARCHAR(64) DEFAULT '代建运营部',
  source_version_no INT,                            -- 回滚时记录源自哪个版本
  change_summary   TEXT,                            -- 本次发布改了哪些节点（摘要）
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
```

### 3.3 `std_node_dependency`（激活既有列，无需 ALTER）

DDL 已有 `version_no/is_active/effective_from`，仅需在读写逻辑中启用，并把现有 NULL 值初始化为 `1/1/NULL`（见 §7 迁移）。

## 4. 引擎改造（**必须**，精确 diff）

文件 `db/engine.py` `_load()`（第 49–58 行）。版本化后引擎**只认生效集**，否则回滚旧行会污染计算。

```python
# 改前（第 49-50 行）
cur.execute("""SELECT std_node_id, depend_std_node_id, depend_row, offset_days, base_is_t0
               FROM std_node_dependency""")
# 改后
cur.execute("""SELECT std_node_id, depend_std_node_id, depend_row, offset_days, base_is_t0
               FROM std_node_dependency WHERE is_active=1""")

# 改前（第 56-58 行）
cur.execute("""SELECT std_node_id, branch_order, is_default, conditions_json,
                      depend_row, offset_expr, direction, base_is_t0
               FROM std_node_rule ORDER BY std_node_id, branch_order""")
# 改后
cur.execute("""SELECT std_node_id, branch_order, is_default, conditions_json,
                      depend_row, offset_expr, direction, base_is_t0
               FROM std_node_rule WHERE is_active=1 ORDER BY std_node_id, branch_order""")
```

> 注意：`project_node_rule`（项目级 override）**不加** `is_active` 过滤——版本化只针对标准库，项目级覆盖保持「当前即生效」。

## 5. 保存逻辑改造（app.py）

现有两处保存：

- `edit_std_node()`（非参数化 dependency，第 298–348 行）：UPDATE/INSERT 单条 `std_node_dependency`。
- `edit_std_node_rules()`（参数化 rule，第 353–447 行）：DELETE+INSERT 该节点全部分支。

**改造原则**：保存时把该节点「旧行」置 `is_active=0`（保留历史），插入「新行」`is_active=1`，`version_no` 取**当前工作版本号**（`std_rule_version` 最大号，无则 1）。即保存 = 更新工作副本，不直接成版。

```python
# edit_std_node_rules() 保存段示意（伪代码）
cur.execute("UPDATE std_node_rule SET is_active=0 WHERE std_node_id=? AND is_active=1", (nid,))
for i, b in enumerate(clean):
    cur.execute(
        "INSERT INTO std_node_rule(std_node_id,branch_order,is_default,conditions_json,"
        "depend_row,offset_expr,direction,base_is_t0,version_no,is_active) "
        "VALUES(?,?,?,?,?,?,?,0,?,1)",
        (nid, i+1, 1 if b["is_default"] else 0,
         json.dumps(b["conditions"], ensure_ascii=False), b["depend_row"],
         b["offset_expr"], b["direction"], cur_work_version()))
# —— 同样处理 edit_std_node 的 std_node_dependency ——
log_rule_change("标准库", nid, None, "更新规则", before, clean_to_front(clean))
```

> 保存后页面提示：「已更新工作副本，记得在「标准库版本」中点『发布版本』固化。」

## 6. 发布 / 回滚逻辑（新增）

### 6.1 发布版本（`POST /std-rule/publish`）

```python
def publish_version(name, effective_from, note):
    con = db(); cur = con.cursor()
    cur.execute("SELECT COALESCE(MAX(version_no),0) FROM std_rule_version")
    new_v = cur.fetchone()["COALESCE(MAX(version_no),0)"] + 1
    # 复制当前生效集为 new_v（旧版 is_active=0）
    for tbl in ("std_node_rule", "std_node_dependency"):
        cur.execute(f"UPDATE {tbl} SET is_active=0 WHERE is_active=1")          # 旧版退役
        cur.execute(f"INSERT INTO {tbl} (std_node_id,branch_order,is_default,conditions_json,"
                    f"depend_row,offset_expr,direction,base_is_t0,version_no,is_active,"
                    f"depend_std_node_id,offset_days,effective_from) "
                    f"SELECT std_node_id,branch_order,is_default,conditions_json,depend_row,"
                    f"offset_expr,direction,base_is_t0,{new_v},1,depend_std_node_id,offset_days,"
                    f"{esc(effective_from)} FROM {tbl} WHERE is_active=1")       # 注意：退役后需先读后插
    # ↑ 实现要点：先 SELECT 当前生效集到内存，再 UPDATE is_active=0，再 INSERT new_v，避免自引用覆盖
    cur.execute("INSERT INTO std_rule_version(version_no,name,note,effective_from,operator,change_summary)"
                " VALUES(?,?,?,?,?,?)", (new_v, name, note, effective_from, operator, summary))
    con.commit()
```

> ⚠️ 上例 `UPDATE` 与 `INSERT...SELECT` 同表会自覆盖，正确顺序是**先 SELECT 生效集到内存 → 再退役旧版 → 再插入新版**。具体实现用内存缓冲，不要同表 SELECT+INSERT。

### 6.2 回滚版本（`POST /std-rule/rollback/<v>`）

```python
def rollback_version(v):
    con = db(); cur = con.cursor()
    before = snapshot_active()                       # 当前生效集（前端格式），用于日志
    cur.execute("SELECT COALESCE(MAX(version_no),0) FROM std_rule_version")
    new_v = cur.fetchone()[...] + 1
    rows = SELECT * FROM std_node_rule/std_node_dependency WHERE version_no=v   # 目标版本全部行
    # 退役旧版 + 插入 new_v（is_active=1），逻辑同发布
    cur.execute("INSERT INTO std_rule_version(version_no,name,note,operator,source_version_no)"
                " VALUES(?,?,?,?,?)", (new_v, f"回滚自v{v}", ..., operator, v))
    log_rule_change("标准库", 0, None, "版本回滚", before, snapshot_version(v))  # 复用既有日志函数，传 con 复用连接
    con.commit()
```

> **坑（交接文档 §五）**：`log_rule_change()` 在事务内调用必须传调用方 `con` 复用连接，否则 SQLite 报 `database is locked`。回滚的多个写操作放同一事务，`log_rule_change(..., con=con)`。

## 7. 数据迁移（初始化基线 v1）

现有数据无版本标记，需跑一次迁移脚本 `db/init_rule_version.py`：

```python
# 1. std_node_rule 补列后，全部置 is_active=1, version_no=1
# 2. std_node_dependency 既有列可能 NULL → 补默认值
UPDATE std_node_dependency SET version_no=COALESCE(version_no,1), is_active=COALESCE(is_active,1)
       WHERE version_no IS NULL OR is_active IS NULL;
# 3. 插基线版本目录
INSERT INTO std_rule_version(version_no,name,note,operator)
       VALUES(1,'初始基线（绿城2026版）','系统初始化导入', '代建运营部');
```

> 双库通用：`dbconn.py` 已双模式；`effective_from` 在 SQLite 为 TEXT、MySQL 为 DATE，均用 `'YYYY-MM-DD'` 字符串互操作。迁移脚本经 `dbconn.get_conn()` 执行，不硬编码 MySQL 连接。
