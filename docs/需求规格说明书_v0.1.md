## 1. 项目背景与定位

代建运营部统筹管理多个住宅代建项目的开发建设。目前开发计划依赖 Excel 在各项目、各部门间传递，存在**版本不统一、进度不透明、预警滞后、计划与投资测算脱节**等问题。

本系统定位为：**代建总部对多项目开发计划进行"编制—审批—跟踪—预警"的中枢平台**，并为投资测算团队提供可复用的计划与工期数据，最终实现"一个项目一张计划网、总部一屏看全局"。

**核心价值主张**
- 用**标准工期库 + 模板**替代从零编制，提升计划编制效率；
- 用**结构化计划数据**替代 Excel，版本可追溯、跨项目可汇总；
- 用**自动偏差计算 + 预警规则**替代人工盯表，风险早发现；
- 用**计划节点数据**支撑投资测算（货值、回款节奏）。

## 2. 用户角色与权限（MVP 范围）

> MVP 先服务"代建总部/运营部"，其余角色为后续扩展。

| 角色 | 职责 | MVP 是否纳入 |
|---|---|---|
| 代建总部 / 运营部管理员 | 建项目、套模板、审批计划、看全局看板、配规则 | ✅ 纳入 |
| 运营部计划专员 | 编制/维护计划、填报跟踪、处理预警 | ✅ 纳入 |
| 项目团队（PM/工程/成本/设计/招采/营销） | 编制本职能二级计划、填报实际进度 | 🔜 P1 |
| 投资测算 / 可研团队 | 查看/导出计划节点与工期，支撑测算 | 🔜 P1/P2 |
| 委托方 / 甲方 | 只读查看里程碑与进度 | 🔜 P3 |

**权限模型建议**：组织层级（总部→项目）+ 角色 + 数据范围（可看哪些项目）三维控制。

## 3. 业务边界与业态

- **纳入**：住宅类代建项目（含分期/组团）的开发进度计划全周期管理。
- **暂不含（P2+ 扩展）**：资金/投资计划、货值计划、招商运营计划、非住宅业态。
- **业态差异点**：保障房/安置房在报建、交付标准上与商品房不同，标准工期库需按子业态区分。

## 4. 计划管理体系（核心）

### 4.1 计划层级定义

| 层级 | 名称 | 典型内容 | 编制主体 | 管控重点 |
|---|---|---|---|---|
| L0 | **里程碑计划** | 拿地、方案批复、开工、预售证、竣备、交付 | 总部运营部 | 关键节点、对外承诺 |
| L1 | **一级计划** | 项目总控节点（设计、工程、招采、营销主线） | 总部/项目 PM | 跨职能协同节奏 |
| L2 | **二级计划**（含"二级*"） | 各职能专项计划：设计二级、工程二级、招采二级、营销二级、成本二级 | 各职能负责人 | 落地执行、资源排布 |

> ⏳ **待用户明确**：你提到的"二级*"具体含义你将在后续补充说明（原暂按"各职能线的二级专项计划"理解，以你的说明为准，不在此下定论）。

### 4.2 单节点/任务属性

每个计划节点（任务）建议包含：

| 属性 | 说明 |
|---|---|
| 基本信息 | 节点编码、名称、所属层级(L0/L1/L2)、职能线 |
| 工期 | 计划开始/结束、标准工期(天)、责任部门/责任人 |
| 依赖 | 前置节点、逻辑关系（FS/SS/FF/SF）、里程碑约束 |
| 实际 | 实际开始/结束、完成%、填报时间、填报人 |
| 偏差 | 计划 vs 实际偏差(天)、状态(正常/预警/延期) |
| 其他 | 是否关键路径、是否对外承诺节点、备注 |

### 4.3 计划版本机制

- 每个项目保存**计划基准版本**（审批发布后冻结）与**过程版本/草稿**；
- 支持版本对比、快照，记录调整原因（应对 Excel 版本混乱痛点）。

## 5. 标准工期库与模板库（解决"缺标准"痛点）

| 能力 | 说明 |
|---|---|
| 业态标准工期 | 按子业态（商品房/保障房/安置房）沉淀关键节点标准工期 |

```
     │                                        │

  项目主数据 ──────────────────▶ 提交审批 ──▶ 发布基准版本

                                  │
                                  ▼
                         经营看板汇总 / 复盘沉淀标准库
```

## 8. 关键数据模型（概览）

| 实体 | 关键字段 |
|---|---|
| 项目 Project | id、名称、业态、分期、委托方、状态 |
| 计划版本 PlanVersion | id、项目id、版本号、状态(草稿/基准)、发布时间 |
| 计划节点 PlanNode | id、版本id、层级、职能线、计划起止、实际起止、责任人、前置依赖、状态 |
| 工期模板 Template | id、业态、层级、节点定义、标准工期 |
| 预警规则 AlertRule | id、层级/节点类型、阈值(天/%)、通知对象 |
| 角色/权限 | 角色、组织范围、数据范围 |

## 9. 非功能需求（初拟）

- **性能**：百级项目、万级节点下看板秒开；甘特图流畅。
- **安全**：组织/角色/数据三维权限；操作日志可追溯。
- **可扩展**：计划体系、业态、预警规则可配置，避免硬编码。
- **可集成**：预留与投资测算、财务/成本/销售系统的数据接口。

---

## 10. 技术架构建议（Web 后台）

- **前端**：Vue3/React + 甘特图组件（如 dhtmlx-gantt / 自研）
- **后端**：Java(Spring Boot) / Node(NestJS) 任选，REST API
- **数据库**：PostgreSQL / MySQL；节点表需支持层级与依赖递归
- **审批/预警**：工作流引擎 + 定时任务计算偏差
- **部署**：内网部署，后续可容器化

---

## 11. MVP 范围与迭代路线

- **P0（MVP）**：总部运营部可用——项目建档、工期模板库、里程碑+一级+二级计划编制（甘特图）、审批、填报跟踪、偏差预警、多项目看板。
- **P1**：项目团队协同、投资测算对接、移动端。
- **P2**：参数化工期、资金/货值计划、外部系统对接。
- **P3**：运营计划、委托方门户、AI 预测。
